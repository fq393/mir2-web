# 商品分类、逐件库存与上框返回

2026-09-11。用户截图指出底部白色返回并非目标呈现，并要求点击同名商品进入逐件列表。

## 来源边界

固定旧Delphi `f829679d24acb3a097d396d737ab067db2c88ca2` 的FState.pas：DMerchantDlgDirectPaint把带@命令的对话链接画成黄色下划线，选中时绿色；DMenuDlgDirectPaint绘制商品名、费用和持久，在SubMenu>=1时另画#31子菜单标记。该候选有2006修改注释，不能认证每个细节等同2003国服。

因此撤销之前自加在商品列表底部的白色“返回商品分类/返回商店菜单”。上方对话框显示黄色“返回”、绿色悬停；位置按当前对话内容预留，不宣称所有原NPC脚本固定同一坐标。

用户记忆中的“有个数”仍需原截图证据：当前旧代码支持子菜单标记，不能据此认定库存数字。Crystal新货模板不一定表示有限实物库存，不能把一个模板显示成“只剩1件”，也不能伪造多件新货。用户随后明确不要名称右侧的小箭头，本轮不显示该指示符，也不虚构库存数字；仅保留文字点击进入二级，底部原翻页按钮不变。

## 本轮变化

- 一级按物品定义分组：点击名称直接进入对应同名实例列表，作为用户确认的交互；不再要求一级先选中再按OK。
- 二级保留每件UniqueID、附加属性、当前/最大持久和独立价格；选择不直接扣款，确认购买发出所选UniqueID。
- 上框返回：二级→一级；一级→NPC主菜单。保留已有跨窗口兼容鼠标事件去重和面板阻断，不因重建窗口连退两层。
- 不额外合并同名不同定义ID，避免不同要求/性别物品混为一类。
