# 1.76 系统与功能主清单

更新：2026-09-11。按工程交付划分 **14个游戏系统＋4个支撑系统，118个功能验收单元**。这不是官方宣称的系统数量，也不是已认证规则数量。当前状态：{'部分': 64, '待考证': 29, '未接入': 25}。没有把整模块或尚未复验的历史记录新标为完成。

本文是 `docs/TASKS.md` 的当前明细表；旧编号及历史复选项保留作证据，不作为另一套实时状态。新编号固定为 `SYS-系统号-功能号`，不得复用。技能和地域还需按模板逐对象拆分，因此此数目不等于最终开发工作量或完成率。

## 状态与验收规则

- **部分**：有局部实现/历史验证，尚缺本行验收条件；依据链接是范围证据，本轮没有重新实测游戏。
- **未接入**：当前网页完整流程未交付，不等于上游没有引擎类/协议；可能已有底层支撑。
- **待考证**：版本归属、具体行为或数值未确定；可研究和测试现有机制，不能直接开放为原版规则。
- **已验收**：未来仅在本行所有条件满足、来源可追溯、实景及需要的持久化检查完成时变更。
- **P0**：崩溃、复制/丢物、身份错误、输入穿透；**P1**：比奇可玩闭环与忠实呈现；**P2**：依赖更广地域/高阶玩法；**P3**：额外平台。P0交易子项仍先依赖交易邀请/托管入口，不意味着跳过依赖。

每行的末栏是验收条件；验证方式：UI项做真实浏览器操作和原图对照，资产/战斗项做服务器边界测试＋真实操作＋重登，概率做配置映射和可复现抽样，资源做哈希/像素/实际试听。每次执行只选一个功能中的可交付切片；超过5个文件或3个独立结果时拆为 `.a/.b` 子任务，不能直接宣称整行完成。

共同异常矩阵：正常、重复、取消、超时、满包/负重/金币上限、无效对象、离店/跨图、死亡、断线、重登/重启；不适用项记录理由。资产操作必须用隔离账号、两端及存档核账。测试版本/命令/截图/日志路径/结论回填专项文档。
