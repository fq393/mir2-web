# 完整流程验收与主动查缺

用户负责体验反馈，不承担穷举1.76需求的工作。开发按本文件主动发现遗漏，模块仍统一登记在TASKS.md，细分执行队列在tasks/todo.md。

## 完成标准

每个流程必须记录：原版入口与素材；正常操作；拒绝/取消/边界；影响的其他系统；重登/断线/重启后的结果。实现、自动测试、真实操作验收分别记录。一个按钮能用或一个用例通过，不等于整个模块已完成。

来源按具体问题取证：本地固定原包核对画面/声音；固定旧客户端核对窗口及输入；旧服务端与可核对版本资料核对规则；Crystal核对当前执行实现。每条结论记录来源版本、位置、差异与未确认范围。社区帖子是线索，不能单凭“1.76”标题把后期扩展当官服规则。

## 每批执行与审计

1. 从当前依赖队列选一个完整用户流程，先查相应客户端处理器、服务端校验及原图。
2. 顺着输入、请求、回包、其他窗口、持久化追踪，主动登记遗漏。已存在模块写回原编号，避免重复任务。
3. 实现后测试成功、取消、失败与跨系统联动；涉及经济必须核对唯一编号与重登一致。
4. 用隔离账号实际操作；源码测试与实景结果分别记录，未测不可写成通过。
5. 更新清单和证据。每完成P阶段，复查该阶段所有入口及相邻系统，而不是等待新的用户截图。

地域按新手出生→比奇补给→野外练级采集→商店/修理/仓库→洞穴→周边地域推进。后续地区沿用已验收的基础流程，增加其专有怪物/NPC/地图/任务证据。

这套方法减少遗漏，但不声称能从非完整史料一次性保证100%官服复原；差异和证据缺口持续公开在清单中。
