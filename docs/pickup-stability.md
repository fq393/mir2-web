# 战斗后拾取掉线：复现与修复

2026-09-09。优先级 P0；用户报告稻草人死亡后，走到金币上出现“闪退”。

## 根因

不是金币加法或服务进程崩溃。隔离环境的一级战士实测复现：连续攻击杀死稻草人，立即点击金币，客户端在走路确认前主动重连，金币仍为10000、serverReady=false。

客户端过去每0.8秒按动画结束再次发送攻击；当前固定的Crystal引擎按真实属性控制AttackTime（本例约1.386秒）。网关串行等待UserLocation，但浏览器仍不断发送，使后续攻击滞留WebSocket接收队列。怪物死后还继续处理旧攻击，走路排在队尾，触发客户端3秒移动超时。复现日志中客户端04:51:19Z已重连，旧连接却直到04:51:23.783Z才执行walk，04:51:24.341Z才返回位置。

依据为固定上游Crystal的HumanObject.Attack/AttackTime和MirConnection.Attack重试队列；这是网页适配层时序缺陷，不调整原引擎攻速、掉率、金币范围或拾取归属规则。

## 修复范围

- 攻击、施法、采集共用一个待确认动作；动画播完不等于服务器处理完。
- 动作附带独立序号，网关将序号和命令随真实UserLocation回传；仅匹配的确认释放等待。
- 待确认期间保留玩家新选的路径，暂不发走路和拾取，防止移动超时从排队期间计时。
- 网关拒绝施法时显式返回同序号actionRejected，避免等待永远不释放。
- 换图、断线、新角色登录清除待确认状态。
- JSON解析错误与游戏回包处理异常分开。后者保留最近20条路由和调用栈，不记录原始回包、账号密码或聊天内容；只读__MIRQA可查看。

## 验证

- 回归测试先在旧代码失败：未确认的攻击继续发送、重复施法/采集堆积。
- Node 106项通过，TypeScript检查通过，.NET构建通过。
- 真实Crystal测试覆盖：金币概率/范围、掉落归属、满包拒绝与释放后拾取、过期消失、死亡刷新、采集满包重试、物品唯一ID和买卖余额等。
- 浏览器实景通过：一级战士连续攻击杀死稻草人后，立即点击金币，10000→10171，serverReady=true、pendingAction=null、连接错误为空。随后点击药品，地面掉落清空，包裹增加金创药（小量）UniqueID=12，金币未重复增加。
- 重启隔离服务器、刷新并重新登录：金币仍10171、药品仍同一UniqueID且数量1，位置304:626。截图与只读状态证据在本地docs/qa/pickup-*.png/json。
- 同批聊天底色校准：固定Crystal `Client/MirScenes/Dialogs/MainDialogs.cs` ReceiveChat及Update使用白底深绿Hint与AutoSize标签。网页此前块元素把底色铺满386px，改为随文本宽度；实景“欢迎来到热血传奇。”为108px、“和平攻击”为48px。此依据是固定参考客户端，不宣称完整官服1.76字体校准已完成。

隔离环境端口17180/17610，专用测试账号与数据库。为稳定复现，仅隔离掉落表设为金币和金创药必掉；主服原掉率和玩家存档未更改。复现与验证日志保留在本地.runtime，含用户现场的原日志不上传GitHub。
