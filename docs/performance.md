# 资源与性能

## 已实施

- 比奇地图按区块加载/释放，保留当前视野和必要建筑锚点；过期异步请求不替换新地图。
- 角色/UI常用图集固定驻留，场景图集随区块释放；已验证切图取消和异步释放。
- 图集帧索引按atlas分桶，新增室内资源显式注册。原实现每张图集扫描全部约万帧；新实现注册时一次分桶，加载只访问本图集。回归用2000帧/20图集验证加载期不再扫描atlas字段，并验证后注册地图资源。
- 原像素NEAREST与关闭WebGL MSAA同时启用，避免非整数缩放拼片黑缝。保持800×600逻辑画面，4:3等比显示。
- 本地HTTP改为`Cache-Control: no-cache`：允许存储并用Last-Modified校验，未修改的文件返回304；不能将没有内容哈希的URL设为永久缓存。
- 服务端属性快照100ms采样，变化才发送、最多1次/秒；即时HP/MP仍走原包。
- 音频首次交互解锁、按需加载、隐藏/静音停止；不在后台无意义持续播放。

## 后续优化须先测量

- 持续记录启动耗时、资源传输、驻留图集/GPU内存、draw calls、稳定行走/切图的帧耗时p50/p95。
- 避免每帧排序不变的场景节点、重复设置不变的SpriteFrame裁剪，实测后逐项调整。
- 构建产物启用内容哈希后再使用immutable/CDN长期缓存；生产压缩与预加载必须检查实际命中率。
- 微信小游戏分包、远端资源、低内存设备和前后台恢复尚未测试。原始像素校验先行，不以有损压缩破坏原图来换体积。

代码仓库不分发原始客户端、生成资源、截图和本地数据库。资源在本机按固定输入/哈希转换；新环境需自行准备有权使用的资源。
