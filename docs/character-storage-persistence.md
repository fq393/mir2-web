# B03 角色仓库存档基础

状态：存档基础已实现并测试；尚未开放NPC或存取功能，不能称为仓库系统已完成。

## 已实现

- 存储按CharacterInfo对象和持久角色Index归属，不使用Crystal.Account.Storage作为角色仓库。
- 容量由未来已核对的内容配置传入；这一层不设1.76容量默认值。4096是损坏文件的防御上限，不是游戏仓库格数。
- 物品沿用Crystal.UserItem序列化，保留UniqueID、数量、持久、额外属性；加载后重新绑定物品定义。
- 仓库扩展写入同一份账号快照末尾，与背包一起经过现有完整临时文件及原子替换路径，不增加第二份异步仓库文件。
- 没有初始化仓库时不追加内容；已有旧存档可读取为空仓库。扩展具有magic和版本标记，未知版本、无效归属、越界容量、重复物品、未知物品定义、截断或多余数据拒绝加载。
- 整个扩展解析、校验成功后才替换内存存储，解析失败不会清空既有仓库。
- 同账号角色独立；发现仓库与背包/装备/任务包/交易暂存/账号仓库的物品ID重复，拒绝写入；不同角色仓库之间也不允许重复ID。
- 已初始化容量不能隐式改变，未来扩缩容需要显式迁移策略。

## 验证

CrystalContentTests新增CharacterStorageTests，使用临时测试目录及合成3格仓库，未更改用户账号或原游戏数值。

已通过：普通序列化往返、真实Envir.SaveAccounts/LoadAccounts文件路径、同账号角色隔离、UniqueID/持久1234/+3保留、跨背包和跨角色重复拒绝、隐式缩容拒绝、截断加载不改内存、旧格式无扩展读取。完整CrystalContentTests回归通过，涵盖已有交易跨进程恢复及商店/掉落/地图测试。

## 兼容边界

扩展由受控prepare-engine.py锚点接入；固定上游仓库不修改。新代码读取旧存档兼容，但一旦实际开放仓库存入并写出扩展，不应直接降级到不认识此扩展的旧服务，否则旧服务再次保存可能丢弃扩展。届时发布/回滚必须使用完整账号备份或显式迁移。
