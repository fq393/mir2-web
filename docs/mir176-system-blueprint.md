## 3. 物品是生命周期，不是一张图

物品模板记录类型、基础属性、原图Image/Looks、场景Shape、职业性别要求、重量、价格与持久定义。物品实例记录唯一ID、当前/最大持久、极品附加属性、数量/用途次数及其他已确认状态。地图上的掉落实体再记录坐标、所有者、保护截止与消失截止。三者必须分开。

```text
怪物/商店/采集/任务/玩家死亡
    → 物品实例（唯一ID，属性与持久）
    → 地面实体（如有：归属、位置、期限）
    → 背包 → 穿戴 / 使用 / 仓库 / 玩家交易 / 出售 / 丢弃
    → 战斗与消耗结果 → 服务器存档 → 断线重登恢复
```

必须逐类检查：普通/极品装备、男女衣服、技能书、药水与药包、肉与矿石品质、符与红绿毒次数、卷轴、祝福/修理油、任务物品、金币；不能把所有“数字”都当作堆叠数量。

### 地面物品定时器

- 当前Crystal `Settings.ItemTimeOut=30`、`PlayerDiedItemTimeOut=120`，单位分钟；本机旧Setup.ini也是这两个值。它们是当前运行默认值，尚无充分证据称为国服1.76原值。
- 普通物品/金币走普通期限；`deathDrop=true`的玩家死亡物品走死亡期限。不能把“怪物死亡爆出”误归入玩家死亡期限。
- `ItemObject.Process`在`Envir.Time > ExpireTime`时移除并Despawn，期限由服务器裁决，网页收到移除后清图与标签。
- 怪物掉落的归属保护当前在MonsterObject内设置为一分钟。归属释放与物品消失互相独立；保护期如何与队伍、杀怪归属相联需专门验收，不能改消失时间代替。
- 本轮后台“地面物品”开放上述两个期限，校验1–10080整数分钟。该上限是管理输入约束，不冒充历史游戏规则；自定义配置重启生效，原基线只读。
- 已实测保存、自定义值重启加载、旧页面重新载入后恢复基线；配置到真实物品/金币期限与过期移除测试通过，见[后台验收](admin-console.md)。
- 联动边界：当前保护期一分钟，普通消失期若设为一分钟，可能在保护结束时直接消失而没有公开拾取窗口。不能把这种配置结果误判为掉落丢失；后续保护参数开放时须联动提示。
- 待完成：保护时间参数化、主动丢弃/死亡规则、同格多物品、金币上限、队伍争抢、离图/拾取/过期竞态、重复ObjectRemove、服务重启地面物品是否恢复的版本规则。

### 极品与名称颜色

- Crystal当前 `IsAdded` 物品地面名为Cyan；普通/None/Common为White；另有Rare/Legendary/Mythical/Heroic品质色。源码明确区分“单件附加”和“模板品质”。
- 本项目已有单件+3、存档、穿戴重算等部分验证，不能把名字变色当作极品系统完成。
- 国服1.76是否在地面直接揭示极品、包裹/装备/交易中如何显示名字，需要旧截图/客户端与协议证据交叉核对。当前Cyan行为属于Crystal适配行为，仍待原味确认；不添加现代蓝紫橙品质层级。
- 补查同一件物品在地面、包裹、装备、悬停、聊天链接、NPC列表、仓库及双方交易窗口的名称、颜色、属性与真实ID一致性。

## 4. 聊天白底问题的校准口径

不凭印象把整个信息框刷白，也不坚持此前的Crystal配色就是1.76。

现有证据：固定Crystal Hint为白底深绿字，普通聊天及其他类型各有前景/背景；旧Delphi FState使用每行的ChatStrs/ChatBks颜色，OPAQUE TextOut绘制文字背景。两者支持“每种消息带独立颜色”，尚不足以证明所有版本的整个信息框底面恒白。

本轮保留“整个底面白色还是原底图”的待校准项，下一轮须收集匹配1.76的全窗截图，逐一对照：普通/私聊双方/队聊/行会/喊话/系统/提示/公告、输入态/非输入态、选中复制/滚动/历史、长句换行、中文输入法和窗口缩放。上轮已纠正文字底色无条件铺满整行，不代表本模块最终认证。

不从传奇3、手游、后期Crystal截图取色；不自行加现代频道侧栏和标签。

## 5. 玩家交易的实施规格（尚未接入网页）

固定Crystal PlayerObject提供TradeRequest、TradeReply、TradeGold、TradeItem、TradeConfirm、TradeCancel，以及背包和交易槽转移；旧Delphi FState存在DDealDlg、DDealRemoteDlg、389背景、391确认原帧。下一步应复用服务器事务与原资源，不另写两个本地数组互换冒充交易。

| 阶段 | 要实现并验证的行为 |
|---|---|
| 发起 | 原入口/快捷键证据，允许交易开关，面向、距离、同图、存活、自身/已有邀请/已有交易检查 |
| 邀请 | 正确目标、接受/拒绝、发起者已离开或死亡时失效，重复邀请不覆盖状态 |
| 展示 | 双方姓名、双方物品与金币、原背景/确认/取消、自己的背包同时可见、不会穿透攻击人物 |
| 放入/撤回 | 服务器校验所有权、槽位、可交易类型、数量/持久/极品、余额；更改报价使双方确认失效 |
| 确认 | 双方明确确认后才交换；单方不能完成，重复确认不会复制；对方改物品/金币必须重新确认 |
| 取消/异常 | 关闭窗口、Esc、移动、换图、死亡、掉线、满包/超重/金币上限，原物与金币恰好返还一次 |
| 保存 | 两账号重登/服务器重启后，金币守恒、实例ID总数守恒、极品/持久不变；提交途中断线专测 |

还需审计当前引擎接受邀请时的再次检查、超时清理、事务完成与返回路径，不能只因方法存在便全部信任。面向/距离和物品限制的最终规则标注来源，不能采用手游40级门槛或现代交易税。

## 6. 原滋原味差异清单

- **已知网页适配**：WASD、空格攻击、点击怪物持续追击、点击大地图寻路、缩放按钮、DOM输入/浏览器字形；用户曾要求的便利行为保留，但不能宣称全部是1.76原生操作。
- **仍有资源身份差异**：Windows原字体、男女布衣/纸娃娃与全部发型武器、原中文招牌、全装备图标与三种外观编号、完整原怪物/技能动画声音。
- **UI仍未完整认证**：聊天全窗底面与所有消息色、名字/血条显示条件、时钟与饥饿映射、全部业务窗口、鼠标携带与长说明、键鼠组合。
- **规则覆盖不足**：全三职业技能、药效/异常状态、持久零、完整物品库与极品概率、红名/死亡掉落、守卫与安全区、仓库和玩家交易、毒材料配方、矿石/炼武器、任务脚本。
- **明确避免默认启用**：英雄/刺客/弓箭手、坐骑、灵宠自动拾取、后期品质分级、宝石强化、休息经验、爆率/经验药、现代拍卖/商城/战令；特戒/套装按逐件历史证据决定。
- **配置并非官方原值**：掉落消失默认30/120、当前候选极品分母、部分经验/怪物/物价/技能字段必须继续保留来源标识；管理员改值后显式为自定义。

## 7. 比奇完成的验收门槛与地域复用

比奇“完成”意味着上述本地可达流程有正向与异常实景，不是比奇地图全部贴图出现。每条至少覆盖正常、限制拒绝、重复操作、满包/超重/金币上限、死亡/距离/跨图、断线重登；涉及资产转移再测两玩家和服务重启。

优先队列：掉落期限后台 → 玩家面对面交易与仓库 → 比奇全商店门点与收购/修理 → 全物种/守卫 → 药剂/书籍/符毒材料 → 三职业技能与队伍分配 → PK/任务 → 全区原图/音频/性能长测。已有P03未完分支仍保留，按前置与风险推进。

可复用：账号、物品实例、交易、背包/仓库、技能协议、掉落与刷新框架、地图流式加载、UI/音频适配、后台配置与测试工具。

仍需逐地域制作：真实地图与门点、中文资源映射、NPC脚本、怪物AI/刷新/掉落、专属技能/特殊入口、照明/BGM和数值证据。沃玛/毒蛇→盟重→封魔→赤月→苍月的详细依赖见[地域计划](world-progression-plan.md)。不能保证“比奇做完后其他地图都很快”：有些区域主要是数据装配，矿区、赤月、苍月和攻城仍包含专门机制。

## 8. 主动维护方式

每次新增物品、怪物、NPC或技能，必须检查其上游获得方式和下游用途，以及UI/声音/后台/存档/失败分支；一处改动至少复查相邻流程。每轮从论坛技术区/旧包/Wiki补查一组相关问题，记录确切来源和是否适用于1.76，不以首页广告代替规则研究。

新发现优先归入既有75项，追加具体子任务；只有确为新系统才增加模块编号。未经原素材与实景验收不得勾选完成；已验收遇到新反例应回退为部分。
