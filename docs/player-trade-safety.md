# 玩家交易：引擎安全校验与未完成分支

日期：2026-09-09。范围：ITEM-04 / P03，**部分完成**。本批没有开放网页交易入口，也不代表双方原生窗口已验收。

## 固定来源与复现

引擎来源：[Crystal PlayerObject.cs，固定提交](https://github.com/Suprcode/Crystal/blob/0e315fe327192afe52c3d7357ddd1f5b7e26c5b8/Server/MirObjects/PlayerObject.cs)。`TradeRequest` 从面对的相邻格寻找玩家；`TradeReply` 原本没有重新检查地图、位置、朝向、死亡和允许交易状态。Crystal 是实现参考，不等同于 1.76 全部规则。

在临时数据库和独立地图运行 `tools/CrystalContentTests/PlayerTradeTests.cs`，修复前真实引擎同时复现：

- 没有交易对象时，`DepositTradeItem` 仍将包裹物品移入交易栏。
- 邀请后走远、换地图、死亡、转身或关闭允许交易，仍能接受邀请。
- 对方包裹满时客户端收到解锁消息，服务器两人的 `TradeLocked` 却仍为真。清出容量后，仅一方再次确认就能交换。
- 金币容量不足分支同样没有清理双方确认状态。

## 已实施

`tools/prepare-engine.py` 从固定上游生成 `server/engine/generated/PlayerObject.cs`，使用精确替换次数断言；上游代码变化会中断构建，要求重新审查。原 vendor 未修改，生成文件不上传。

- 接受邀请重新验证相邻、面对、同地图、存活及接收方允许交易。
- 物品/金币存入前验证双方仍互为交易对象，且满足位置、朝向和存活条件。
- 最终确认重新验证位置、朝向和存活条件。
- 容量拒绝时同步清空双方确认状态，保留托管内容，必须重新双确认。

真实引擎回归覆盖：上述拒绝分支；有效邀请与拒绝；满包后不能单方完成交易；金币上限拒绝；正常取消和重复取消；成功交换和重复确认。用带攻击 +3 的同一物品实例检查 UniqueID 所属对象、附加属性和金币守恒。测试只修改临时夹具。

## 开放网页交易前的阻断项

1. **满包取消与断线返还**：上游 `TradeCancel` 在无法放回物品时调用后期邮件系统。网页未提供该流程，不能当作 1.76 返还机制直接上线。需要核对原版的预留槽位/操作限制，并覆盖拾取、购物、奖励、穿脱和切图。
2. **金币返还容量**：金币托管期间通过其他渠道获得金币，取消时的余额容量必须守恒；不得截断、重复入账或转到不可达系统。
3. **负重**：上游 `CanGainItems` 主要检查格子容量，须核对接收负重、取消返还和装备变化的联动。
4. **邀请生命周期**：断线、退出、死亡、切图、重复邀请、邀请方连接替换、旧消息重放；本批未完成真实双连接验收。
5. **原生 UI / 协议**：提取并核对双方交易窗口、金币输入、确认和取消帧；接通协议和包裹携带；窗口变化必须让双方看到最新内容。
6. **持久化与异常恢复**：提交前后断线、服务器重启、重复提交，双账号保存重新登录验收。

## 2026-09-10 补充

反复存入金币时，原 `TradeGoldAmount += amount` 会发生 uint 溢出。新增真实引擎回归先复现托管归零/钱包扣款，再加 `amount > uint.MaxValue - TradeGoldAmount` 拒绝条件，保持两处余额不变。此修复仅覆盖存入溢出，**不代表取消返还容量和整个交易闭环已完成**。基线内容回归改用临时复制的配置，排除线上管理员自定义数值干扰，未修改主账号或后台配置。

## 2026-09-11：预留取消返还容量

真实引擎先复现三处失败：满包存入交易后CanGainItem/CanGainItems仍允许占用腾出的格子；存入金币后CanGainGold仍允许占用返还余额。证据日志在本地.runtime/trade-reserve-before.log。

本次实现：

- 包裹可用格数扣除当前托管物品占用数，拾取/购买容量预检查保留返还空间。逻辑满包仍有物理空格时，叠放分支补空值检查。
- 脱装备、取仓库/精炼物等直接写格子的入口补返还空间保护；不能跳过公共容量检查消耗预留格。上游未开放租借/行会仓库的直接写格点也加保护，不表示开放这些玩法。
- 最终双确认检查与交换期间临时释放双方返还预留，finally恢复保护，避免双方满包各拿出一件后无法正常互换。
- 取消使用实际空格返还，不再将自身托管预留误判为包裹已满；保留物品UniqueID、持久及附加属性。
- CanGainGold和GainGold预留TradeGoldAmount；取消先移出托管计数再退回，避免重复计算。原有超上限收入截断策略没有改成新的游戏奖励规则；有预检查的收入应在付款/拾取前拒绝。
- 固定vendor不修改，生成HumanObject.cs/PlayerObject.cs；csproj改为编译生成版本，导出不包含上游整份生成文件。

验证：CrystalContentTests真实引擎整套通过（本地.runtime/trade-reserve-final.log）。新增满包预留、+3原物品取消、脱装备拒绝、主动撤回、金币容量、重复取消、双方满包互换及临时保护标记恢复；既有购买/旧货/掉落/技能等回归通过。此次未改主账号、未重启主服务，运行中的主服务尚未加载这版引擎；网页交易仍未开放，不提供不存在的双浏览器成交验收。
