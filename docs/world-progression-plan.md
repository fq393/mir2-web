# Mir2 1.76 世界与流程实施规划

目标是可连续游玩的中文系统。先把比奇省做完整，再沿地图和玩法依赖扩展；不能用一张地图、一排按钮或一个回包代表系统完成。2026-09-08。

## 版本与证据

1. 固定客户端仅证明地图、图形、声音；固定 Crystal 源码证明当前执行逻辑，不能证明中国官服数值。
2. 怪物基础字段采用两份固定候选 Monster.DB 的交集；刷新和掉落保留原文件行号及来源。候选服中扩展物品、倍率、乱码条目不导入。
3. 1.76存在不同修订阶段。幻境、沙巴克藏宝阁等争议内容单独列入待确认范围；不把现代宣传页、传奇3、传奇归来、传奇永恒当原版证据。
4. 无证据的机制保持待核实，不能为了演示而提高掉率、缩短刷新、赠送高级技能或虚构任务。

来源入口：[旧怪物资料](https://mir.17173.com/monster/monster.htm)、[旧技能资料](https://mir.17173.com/skill/skill.htm)、[固定候选地图与MonGen](https://github.com/mrzhqiang/mirserver-1.76/tree/39e17246a32247a2c43c4cc481e97e88c692fa53/Mir200/Envir)、[另一份候选数据库](https://github.com/pangliang/MirServer-Delphi/tree/f829679d24acb3a097d396d737ab067db2c88ca2/MirServer/Mud2/DB)。引用候选内容不等于认证其官方性。

## 比奇省必须闭合的流程

| 流程 | 必须联动的系统 | 验收场景与当前缺口 |
|---|---|---|
| 创建角色→出生→首次补给 | 三职业/性别、基础属性、出生点、初始物品、金币、存档 | 当前仍是默认战士测试账号；需要完整选角与出生流程 |
| 装备→战斗→经验→升级 | 使用条件、装备属性/重量/持久、攻速/命中、防御、受击、经验归属、等级属性、音画反馈 | 已接原引擎与经验回包；职业属性、全部动作音效、死亡惩罚仍要校准 |
| 刷新→发现怪物→击杀→再次刷新 | 每个出生区域的物种/数量/范围/周期，仇恨、尸体、可用出生格 | 鹿/稻草人候选数据已接；鸡、多钩猫、钉耙猫、半兽人、森林雪人、毒蜘蛛、食人花等需逐类核对素材及数据 |
| 击杀→掉落→走到物品→拾取 | 独立概率、掉落物实例/金币、地面素材、归属保护、过期、容量、重量、同步 | 当前稻草人仅接已有物品白名单；不包含未校准武器/特殊药水。地面拾取已接，不能远程指定物品ID取物 |
| 杀鹿/鸡→挖肉→卖肉→补给 | 可挖尸体、挖取动作/次数、肉的品质和价值、满包、肉店买入 | 鹿候选掉落文件已损坏，肉品概率未导入；原引擎挖取协议已桥接，完整挖肉经济流程待做 |
| 拾到装备→鉴别→穿戴/出售/修理 | 属性提示、职业等级、装备槽、持久损耗、普通修理/特修、商店类型 | 购买与穿戴已接；卖出、修理、肉店、准确物品提示尚未闭合 |
| 买技能书→学习→修炼→升级技能 | 职业/等级、扣书、技能列表、熟练度、MP/符/毒、快捷键、动画音效 | 使用/成长回包与测试已接；书店供货、训练数值冲突、三职业主动技能尚未完成 |
| 进店→交易→出店→离线重登 | 门格与室内地图、NPC距离、物品/金币事务、地图及背包持久化 | 首饰店有真实入口；武器、服装、药、肉、书、杂货及仓库要按地图逐店接入 |
| 死亡→尸体→复活→继续成长 | 死亡掉落/经验规则、复活点、保护、装备/技能/金币保存 | 当前回城复活可用；死亡处罚必须另行核对，不能沿用演示即认定原版 |
| 多人争夺→协作 | 安全区/守卫、攻击模式、名字颜色、组队经验/掉落、交易、聊天、仓库 | 只有基本多人同步；必须增加双人测试与不可重复结算测试 |

上述每条须有正常、失败、重试、断线和重启验收。例如拾取失败不扣金币、不删除物品；目标被别人拾走时清理寻路目标；切图不能保留旧掉落；同一死亡不能重复结算经验或减少两次刷新计数。

## 地域扩展顺序

| 阶段 | 地域与关联区域 | 进入条件与复用系统 | 完成标准 |
|---|---|---|---|
| A | 比奇省：比奇城、银杏山谷、边界村及野外 | 新手补给、基础怪物、商店、仓库、守卫、安全区 | 上述新手循环闭合，区域覆盖、刷新、负载及存档验收 |
| B | 比奇周边：天然洞穴、半兽人古墓、废矿区/尸王相关区域 | 洞穴切图、照明、地下刷怪、挖矿、尸王技能书 | 逐层入口与返回、矿物/书籍经济、精英刷新；地图别名和编号需实际文件匹配 |
| C | 沃玛森林、沃玛寺庙；毒蛇山谷 | 从比奇步行通路、补给点、蛇类与毒、组队、教主机制 | 连续过图不丢存档，完整层级、原怪物和掉落、多人归属 |
| D | 盟重省：土城、蜈蚣洞/死亡山谷、石墓、祖玛寺庙、沙巴克 | 长距离旅行、修理仓储、群体技能、组队；行会是攻城前置 | 先完成练级和打宝路线，再做沙巴克攻城流程及状态持久化 |
| E | 封魔谷、封魔矿区及后续通道/封魔殿 | 多层地图、精英/BOSS刷新、补给与持久消耗 | 所有出口和回路可走，怪物生态及装备产出有出处 |
| F | 白日门、丛林迷宫、赤月峡谷、恶魔祭坛/赤月魔穴 | 道士召唤/治疗/施毒、远近程协作、复杂地图入口 | 三职业技能完整后再验收高难怪物；不能以削弱数据代替功能 |
| G | 苍月岛：尸魔洞、骨魔洞、牛魔寺庙 | 岛屿通行、多层地城、BOSS及高阶装备产出 | 传送/NPC、入口、刷新、归属、掉落、补给及重登全部贯通 |
| H | 六大重装相关地图、桃源之门等特殊区域 | 特定入口条件、职业装备、独立刷新 | 按选定1.76修订资料逐项确认；幻境等争议范围保持独立，不默认开启 |

这是一份实施次序，不是已解锁地图列表。地图编号、门格、怪物和NPC必须从本地文件与固定配置中核对，规划名称不能直接转成游戏传送按钮。

## 通用系统与性能

- 数据按地图/物种/物品分组，保留来源和转换映射；迁移幂等，启动前备份。游戏服务器独立进行随机、经验、库存、归属、尸体和刷新计算。
- 地图与素材按当前场景/视口加载，离开即释放；地面图复用共享原生图集，不逐个物品读取图片。只绘制服务器可见范围内实体，清理删除/切图/断线对象。
- 数量预算以来源表为准；性能不足优先优化空间查询、更新频率和资源生命周期，不能偷偷减少怪物或改变刷新周期。候选密度过大要列为数据争议并测量。
- 记录服务端怪物数量、CPU/内存，浏览器实体数、帧耗时及缓存数量；区分一次采样与持续压测，不能用HTTP200代替性能达标。
- 微信方向单独验证小游戏运行时、分包、资源缓存、触摸输入、前后台断线恢复。服务器规则和协议复用，不复制另一套数值。
