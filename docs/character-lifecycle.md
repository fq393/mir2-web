# 人物删除与角色位复用

2026-09-08，对应 AUTH-02 / AUTH-06。只补原选角画面已有的删除入口，不增加恢复、分页或额外人物位按钮。

## 来源与边界

固定候选 [IntroScn.pas](https://github.com/pangliang/MirServer-Delphi/blob/f829679d24acb3a097d396d737ab067db2c88ca2/MirClient/IntroScn.pas#L1228) 的 SelChrEraseChrClick 对当前角色显示带姓名的确认信息；只有 mrYes 才发送删除。FState.pas 第1048/1060行将删除按钮映射到 Prguse70、(347,506)。DMessageDlg 第2394行起使用 Prguse360，按钮363/367/365，位置(104,126)/(214,126)/(324,126)。三个选项存在时 Enter 不确认，Escape 取消。

全部图像来自用户提供且已固定哈希的 Prguse WIL/WIX。此包的367与365均显示“取消”，保留原像素，不自行重画文字；可访问名称分别为“不删除”和“取消删除”。旧源码和候选资源包之间的文字差异不视为已认证的官方版本一致性。

执行删除使用固定 [Crystal MirConnection](https://github.com/Suprcode/Crystal/blob/0e315fe327192afe52c3d7357ddd1f5b7e26c5b8/Server/MirNetwork/MirConnection.cs#L1037) 的 C.DeleteCharacter 与 S.DeleteCharacterSuccess。引擎设置 Deleted 和 DeleteDate、移出排行，不直接擦除 CharacterInfo。删除恢复的管理能力、历史超额角色迁移仍未实现，不在选角界面创造恢复入口。

## 实现

- 原删除按钮只针对当前可见且选中的角色；无角色时禁用。确认框打开时底层选角/进入/创建不接收输入，姓名用文本节点呈现。
- 取消、Escape 不发送请求；Enter 不默认删除。确认提交后等待服务端，不提前从列表移除。模态框一次只能结束一次，重复点击不能重复提交。
- 服务器检查协议阶段、登录状态、普通账户与角色归属，拒绝体验角色操作、游戏中删除及并发账户请求。成功后移除桥接缓存对应项并发送完整最新列表；失败保留列表。
- 删除最后一位后进入/删除禁用、创建可用；双位容量直接由成功回包后的列表计算。账户按钮等待结束时恢复各自原禁用状态，避免错误反馈把满额创建按钮误启用。
- 断线销毁确认框和待处理界面，重登以引擎数据为准。删除后离线角色信息仍由原引擎存档机制保存。

## 浏览器与存档验收

使用独立17180/17610服务，在原界面真实注册新测试账号并创建角色；没有改写存档或调用页面内部动作来制造结果。

1. 空列表：进入、删除禁用，创建可用。创建“删除流程验收”后，原按钮打开姓名确认框；Enter不删除，Escape及两个取消按钮都保留角色。
2. 点击确认后只在成功回包后移除人物，删空状态正确；退出重登，角色仍不存在，空位可创建。
3. 新建“双位删除验收”“另一人物验收”，确认两位满额时创建禁用。删除前者后，后者保留且创建重新可用。原窗体遮罩阻止点击底层“开始”，Tab进入确认框按钮。
4. 对剩余人物打开确认框但不确认，停止隔离服务：模态立即销毁，回登录页并禁用连接中的表单。重新启动服务登录，列表仍只有“另一人物验收”，此前已删人物没有回来；该人物可实际进入游戏。
5. 常规Node回归66项通过、协议集成通过、TypeScript/Cocos/.NET构建通过；8张新增原图与已有113帧/3段WAV逐字节通过。服务端构建仅有固定上游Packet.cs原有未使用变量警告。

本地截图：`docs/qa/character-delete-confirm.png`、`docs/qa/character-delete-result.png`。不上传带原包图像的截图。

连续协议及浏览器创建曾触发固定引擎按IP记录的创建限制，后一次创建被拒绝；未将失败当作双角色通过。重启隔离服务后重新从真实创建入口完成第3/4项。集成脚本应在新启动的隔离服务上运行，避免与同IP其他创建测试共用限额。该限制对多个本地账户的联动需在OPS-03中继续核对，未修改引擎规则。

模态输入隔离采用HTML标准[inert子树](https://html.spec.whatwg.org/multipage/interaction.html#inert-subtrees)，关闭时恢复原输入状态。浏览器兼容矩阵仍属PLATFORM-02；本轮桌面实测不等同于微信支持。

尚未完成：删除恢复后台、恢复时重名/容量冲突、旧超额人物迁移、删除已提交但尚未回包时强断线、进程非正常退出的恢复矩阵。这些不因本轮成功而划掉。

最终构建补验：Shift+Tab首次落在取消按钮，Enter不默认执行；适应窗口后原452像素宽确认框等比显示为702.86像素，完整位于画布内，取消按钮实际点击正确（`docs/qa/character-delete-fit.png`）。
