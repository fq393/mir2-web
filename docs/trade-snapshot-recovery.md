# 交易中存档快照保护

2026-09-11，SYS-11-08 / SYS-16-04，状态：部分。范围为未成交托管进入账户快照，不代表网页交易已开放。

## 根因与来源

固定Crystal 0e315fe：CharacterInfo.Save保存Inventory，不保存Trade；AccountInfo.Save保存Account.Gold，不保存玩家运行字段TradeGoldAmount。测试直接走原序列化重读，复现托管物品缺失及1000金币只存成990。

## 实现

TradeAccountSnapshot在游戏线程生成账户快照：克隆包裹格数组，把该角色未成交的托管物品放回空格，将同账户在线玩家托管金币加回保存值，再调用原AccountInfo.Save。finally还原在线账户余额和包裹数组引用，不改变Trade、锁定或双方状态。读取仍使用原二进制格式，因此重新启动读取该快照等同于取消未完成交易。若返还格不足、金币越界或出现重复物品ID，拒绝新快照，不静默删物。

普通/异步保存均走同一快照入口。异步备份改为复制旧文件；新文件写完后覆盖替换，避免先移走唯一有效存档。写入错误记录到服务日志并释放句柄、恢复Saving标记；异步数据Flush(true)后才替换。没有新增玩法或邮箱。

## 验证

真实CrystalContentTests整套通过。新增TradeSnapshotTests：

- 原序列化确实遗漏托管；新快照用原AccountInfo读回，UniqueID、攻击+3、持久和金币正确。
- 重复保存不重复退钱；已结算状态不再次返还。
- 在线Inventory引用、余额及Trade字段在成功和模拟I/O失败后均保持原样。
- 非法满包托管拒绝快照；实际BeginSaveAccounts失败后旧文件字节不变且Saving清除，随后有效保存可以完成。

测试只在临时目录和隔离对象运行。日志本地.runtime/trade-snapshot-tests.log。未重启或修改主账号，运行中的主服务尚未加载此轮与上一轮引擎修复。

## 剩余门槛

- 双账号、双浏览器的取消/断线/死亡/跨图实测，以及真实进程强停重启核账。
- 成交确认必须关联可靠落盘；目前仍是周期性存档，最新快照之后的进度可能回退，不能承诺零丢失或完整ACID交易。
- 非法旧状态仍需独立恢复工具；拒绝覆盖旧档只能保护已有有效快照，不恢复旧代码已损失的资产。
- 文件系统断电、目录同步、备份恢复和存档损坏注入仍待验证。临时保存值替换仅允许游戏线程同步调用，禁止后台线程直接调用。
