# 死亡场景与旧货实例保护

## 死亡显示

依据固定 Delphi `PlayScn.pas` 的死亡分支（1417 行 `g_DeathColorEffect`），将世界中的地面、建筑、人物、怪物、掉落图片和特效转为灰度。外部 HUD、聊天和小地图保持各自颜色。使用 Cocos 的 Sprite 灰度材质；死亡/恢复时遍历一次已有场景，新建角色及异步加载地块继承状态，不逐帧扫描全场景，也不重写原图。

逻辑回归覆盖死亡切换、复活恢复、死亡过程中完成的异步地块。实景证据见 `docs/qa/death-gray/`，使用隔离数据库的验收角色受真实怪物攻击至 HP=0；主角色数据未调整。实测死亡 HP=0 后 Alt+X 返回选人，重新进入 HP 18/18、出生点 (288,615)，灰度关闭、场景颜色恢复，两阶段连接错误均为空。114 项 Node 回归、TypeScript 检查、C# 内容回归与网页构建通过。

灰度显示不是死亡系统全部完成：红名惩罚、死亡掉落精确规则、多人观察、特殊状态/跨图死亡仍待核对。

## 旧货修复

固定 Crystal `NPCScript.Buy` 原实现存在两个数据问题：

1. 检查金币及包容量前修改共享库存的 Count，购买失败也会改库存。
2. 部分购买旧货/回购物品时直接删掉整堆，剩余数量丢失。

`tools/prepare-engine.py` 在生成的引擎副本中修复，原固定仓库保持原状：先克隆报价及容量检查，成功后才提交；整件购买保留原 ID、极品属性及持久，拆分时分配新的实例 ID，原实例保留余量。普通商店样板数量不再被报价修改。

真实引擎回归：

- [x] +3 青铜剑的唯一 ID、当前/最大持久、附加属性保留，扣费一次。
- [x] 已售商品的第二次购买不扣费、不复制物品。
- [x] 金币不足、满包失败保留共享数量。
- [x] 分批购买保留余量、不同 ID；买完余量才移除。
- [x] 回购失败及分批回购的数量保护。
- [x] 使用真实 Goods 文件保存、重新创建 NPC 及 LoadGoods：未售 +3/持久/ID 保留，已售品不复生。
- [ ] 浏览器二级目录与旧货原生界面、返回、持久/极品明细。
- [ ] 两个真实连接争购及提交中断线、服务器进程重启联合验收。
