# 1.76 系统重整：分类、依据和执行计划

2026-09-11。用户要求重新分析整套系统、细化遗漏，不再靠逐张截图补需求。本轮只修改规划文档，不修改游戏代码、运行数据或重启服务。

## 结论和范围

工程划分为14个游戏系统和4个支撑系统，118个功能验收单元。详见 [当前功能主清单](system-task-matrix.md)。这是工作组织方式，不是官方固定分类。

| 游戏系统 | 主要模块 |
|---|---|
| 01 账号与角色入口 | 注册登录、两角色位、创建出生、选角开门、删除恢复、会话 |
| 02 人物成长与属性 | 经验表、经验归属、升级、属性重算、成长惩罚 |
| 03 原生界面与操作 | 窗口布局、鼠标键盘、焦点、目标、聊天输入、名字血条 |
| 04 地图与场景 | 比奇分区、中文地名、室内门格、大小地图、跨图、光照 |
| 05 NPC与商店服务 | 身份、服务距离、分类返回、旧货、修理、全商人覆盖 |
| 06 战斗PK与死亡 | 伤害命中、追击、攻击模式、安全区、PK名色、死亡复活 |
| 07 三职业技能与召唤 | 学书键位、各职业逐技能、耗材、宠物、持续效果 |
| 08 物品与装备 | 身份图标、穿脱、极品、药剂、幸运诅咒、特殊效果、卷轴 |
| 09 怪物生态与掉落 | 物种、刷新、AI、守卫、击杀归属、尸体、Boss |
| 10 采集与生产 | 挖肉、毒材料、制毒、挖矿、升级武器 |
| 11 仓库交易与资产 | 仓库存取、金币丢弃、物品丢弃、双人交易、地面保护期限 |
| 12 聊天队伍与关系 | 各消息通道、组队、收益与保护、查看玩家、师徒、婚姻取证 |

## 本轮发现并纠正的清单问题

1. 旧总表声称75项，实际带编号表格83行、79个不同编号；OPS-02/OPS-03/INPUT-01/ITEM-09复用。保留历史，当前表改用SYS唯一编号。
2. 道士仍标“待做”但治愈术自疗已通过；药瓶原图已获用户确认，但旧行仍写未核对。最新范围放回新表，避免倒退或重复实现。
3. 经验系统原来散在HUD/战斗条目中，现拆为独立成长系统；区分经验表真实性、升级结算、属性重算与死亡惩罚。
4. 仓库、交易和丢弃旧时合成一行，现拆9个资产流程；尤其把修改报价解锁、双方提交、取消返还、并发争抢、重启保存单独列出。
5. 缺少系统性的持续技能/宠物实体到期、PK归责、跨区内容依赖、后台生效策略和长时性能验收，现有专属子项。
6. 旧“75项完成度”不再统计。118行是验收单元，技能/NPC/怪物/物品还要逐对象展开，不能当成118个同等工作量任务。

## 当前推荐执行顺序（补充）

用户询问剩余任务与完善顺序，本次核对主表及近期修复记录；只调整计划，不视为重新实测。

1. **当前缺陷收尾**：走跑中F1停步、火球近远时序、切标签后实体恢复、窗口输入不穿透。补真实浏览器操作证据；发生崩溃/资产丢失时优先处理。此批验收完恢复A1，不无限扩大为全部技能重做。
2. **资产完整流程**：按下表A1–A6完成交易邀请、双窗、物品/金币托管、双确认、中断返还和双账号保存；再完成B1金币丢弃、B2仓库，并验证旧货极品两人争买及地面争抢。原子提交与存档检查贯穿，不能只交窗口。
3. **比奇NPC与建筑**：逐店核对铁匠、衣服、书店、药店、首饰、屠夫、仓库的身份、资源、坐标、门点、库存与服务；每店做进门→服务→返回→出门。同步该店物品图标、描述和穿脱/买卖声音。
4. **战斗成长与死亡**：命中伤害、经验升级、属性重算、药物恢复、持久、攻击模式/安全区、死亡灰度及复活；数值待考证项先登记来源，不造精确概率。
5. **比奇生态及三职业入门**：逐怪核对刷新/追击/尸体/经验/掉落/采集，补守卫；按学习门槛和当地资源逐技能接入，包含战士被动、法师及道士耗材链。每个对象同时验收原动作/声音/特效，不全部推到最后。
6. **多人协作与原版界面复核**：组队收益/保护、聊天各通道、玩家交互；逐窗中文字体与布局、登录选角演出、装备逐件听感补全。现有功能的明确错误随所属批次修复。
7. **GM与长期运行验收**：金币等级管理、配置生效标识/校验/回退、受控重启、备份恢复、长时切图和并发压力。安全与性能回归每批执行；本批补完整管理功能与统一验收，不将基础安全留到最后。
8. **后续地域**：比奇周边地牢/矿区→其他地域，分别建立出入口、NPC、怪物Boss、掉落、任务、技能材料和BGM清单；行会沙城按地域依赖取证接入。微信小游戏在网页核心流程稳定后单独做。

每批出口：正常流程、相关失败/取消/断线、需要的重登/重启、浏览器实景和原资源对照。通过才更新对应小项；大模块仍按主表条件判断。发现新问题加入所属SYS项，明确缺陷可插队；独立新增玩法不打断当前链条。来源不足时保留“待考证”，可继续不依赖该数值的任务。

## 执行依赖与下一批次

先资产安全/可玩基础，再三职业完整流程，之后扩区。每行大功能仍按小切片交付，不一次修改整个系统。当前先补近期输入/特效/标签恢复的实景验收，随后下一功能批明确为交易闭环；不因技能刚有进展就只连续补技能。

| 顺序 | 子任务与归属 | 前置 | 主要改动位置 | 验收与检查点 |
|---|---|---|---|---|
| A1 | SYS-11-05.a 交易邀请/拒绝/取消入口 | 固定原Trade窗资源及交互证据 | Program.cs、MirWorld.ts、新TradeUI、专项测试 | 两个隔离账号双方显示身份；拒绝/取消无资产变化；不得用商人窗顶替 |
| A2 | SYS-11-06.a 双方物品托管及撤回 | A1 | 交易UI、桥接、引擎补丁及测试 | 一件普通/一件极品往返；唯一ID持久属性一致；修改后锁定清除 |
| A3 | SYS-11-06.b 金币托管 | A2 | 同上，原金额弹窗 | 负数/越界/余额不足/重复提交；账面+托管总额不变 |
| A4 | SYS-11-07 双确认与容量复核 | A2/A3 | 桥接、交易UI、引擎测试 | 成交一次；满包/负重/金币上限拒绝；双方资产守恒 |
| A5 | SYS-11-08.a 取消/死亡/离图/断线返还 | A4 | 状态清理、引擎测试、浏览器脚本 | 每个中断点各测双方返还；无只到账一边或物品复制 |
| A6 | SYS-11-08.b 双账号重登/重启保存 | A5、SYS-16-04 | 保存实现及隔离测试 | 成交和取消两套账号分别重启核账；通过后才勾交易闭环 |
| B1 | SYS-11-03 金币输入携带丢弃 | A3可复用金额校验 | 原弹框、MirWorld、桥接、测试 | 取消不扣、落地无数量标签、拾回余额一致；与期限并发 |
| B2 | SYS-11-01.a 原仓库往返一件极品 | B1、资产测试基础 | NPC服务、仓库UI、桥接、测试 | 存入取出、满包失败及重登；不得共享错账号 |
| C1 | SYS-05-01/04-03 每次一处NPC/建筑 | 已有门点基础 | 内容表、地图注册、覆盖表、测试 | 衣服/铁匠/书店/仓库逐店双向走入走出和正确服务 |
| C2 | SYS-09-01/04 每次一种怪物或守卫 | C1和安全区证据 | WildlifeSeed、内容表、资源转换、测试 | 原AI/图/音/伤害/尸体/刷新通过；未核坐标不乱补 |
| D1 | SYS-07-03.a 治愈双人及异常 | 现有自疗 | MirWorld、引擎测试、双账号浏览器 | 满血低蓝、别人治疗和远端同步、保存；补现有自疗边界 |
| D2 | SYS-07-04.a 基本剑术被动 | 成长/命中来源 | 技能UI/引擎映射/测试 | 学习后准确及熟练度真实变化；不要给被动做主动特效 |

A2/A4/A6为检查点：构建、针对性回归、真实双账号、源资产对比；失败先修，未完成不推进同链下一步。其余系统按主表优先级并列保留：成长数值、全装备听感、聊天样式、GM角色调整在后续批次各单独交付。遇到版本证据阻塞写明字段和来源冲突，可转向独立任务，不能编规则解除阻塞。

## 比奇完成门槛与扩区

比奇不是“地图能走”就完成：本表跨系统流程1–12涉及的比奇范围要能实测；逐NPC与怪物覆盖、三职业入门到当地可获得技能/耗材、正确资产流转和死亡复活须交付。矿区及更高阶技能若依赖后续地图，明确属于下一地域，不让比奇标签掩盖缺失。

可复用：协议、背包交易、技能执行、任务脚本、资源转换、门点加载。每张新图仍须核对入口、碰撞、名字招牌、NPC、AI/掉落、BGM、任务和性能，不能承诺剩余地图很快全成。范围不明的地域和玩法先取证，不开放后期内容。
